# 第 14 讲：参数高效微调与高效推理

> **课程定位**：2026 年课程核心微调与推理；复用 DLOpt 2024 课件，部分性能数字属于文献实验条件而非保证值。
>
> 配套文件：`materials/Lecture-14_Efficient-Fine-Tuning-and-Inference/01_efficient-fine-tuning_slides.pdf`、`02_efficient-inference_slides.pdf`

## 学习目标

把“训练阶段省什么”和“推理阶段省什么”分开：前者主要缩小可训练参数、梯度与优化器状态，后者主要管理 KV Cache、注意力计算和请求调度。应能说明 LoRA、DoRA、LISA、GQA/MLA、StreamingLLM、vLLM 和投机解码各解决哪一环。

## 1. 先选微调策略

**核心掌握决策。**

- **Prompting**：不改权重，适合快速原型和已有能力。
- **RAG**：运行时检索外部资料，适合动态、可追溯的知识。
- **Fine-tuning**：用数据稳定改变行为/格式，适合固定任务和专业能力。

微调可以看作从预训练的良好初始化出发，继续最小化任务损失。全参数微调保存全部参数的梯度、优化器状态和激活，对数十亿参数模型很贵；为每个下游任务保存整份权重也不方便部署。

## 2. 参数高效微调方法

### BitFit

**了解。** 只训练偏置 $b$，冻结权重和多数参数。实现简单，但表达能力有限。

### Adapter

**熟悉。** 在每个 Transformer 模块插入小的 bottleneck 网络，冻结主体参数，只训练 adapter。它会改变层结构，部署时需兼容 adapter 模块。

### LoRA

**核心掌握。** 冻结原权重 $W_0$，学习低秩增量：

$$
W'=W_0+\Delta W
=W_0+\frac{\alpha}{r}BA,
$$

$$
B\in\mathbb R^{d\times r},\qquad
A\in\mathbb R^{r\times k},\qquad
r\ll\min(d,k).
$$

其中 $W_0\in\mathbb R^{d\times k}$，可训练参数从 $dk$ 降为 $r(d+k)$。通常初始化 $A$ 很小/随机、 $B=0$，使增量初始为 0；这样训练起点与原模型一致。推理可把缩放后的 $BA$ 合并进 $W_0$，但需要先确认量化、融合与精度策略。

**内存收益：** 主要节省被冻结参数的梯度与 Adam 状态；模型权重和部分激活仍然存在。LoRA 不自动减少前向矩阵乘的 FLOPs，部署合并后才可能获得低延迟。

### LoRA+

**熟悉。** 对 $A,B$ 使用不同学习率，改善某些设置下的优化效率。两因子初始化和梯度尺度不同，统一学习率未必合适；这不是所有任务上不同学习率都更优的保证。以 $B=0$ 初始化时，首步 $\nabla_A L$ 为零而 $\nabla_B L$ 可非零，不能仅凭哪个因子为零判断哪个先更新。

这里 $L$ 指经 $BA$ 作用于模型的任务损失；若另加直接作用于因子的正则项或解耦权重衰减， $A$ 的实际首步参数变化还需单独计算。

### DoRA

**熟悉。** 把权重分成幅度与方向：

$$
W_{:,j}=m_j\frac{V_{:,j}}{\Vert V_{:,j}\Vert _2},
\qquad j=1,\ldots,k,
$$

这里 $V=W_0+\Delta V\in\mathbb R^{d\times k}$， $\Delta V$ 用低秩因子表示； $m\in\mathbb R^k$ 是可训练列幅度。初始取 $m_j=\Vert (W_0)_{:,j}\Vert _2$，各方向列需非零（数值实现通常另设保护）。这是课件列归一化约定，转置权重布局的实现可能按行归一化。训练幅度与低秩方向增量，将“方向改变”和“尺度改变”分开，但不是把完整 $V$ 的所有元素都设为独立可训练参数。

### LISA

**熟悉。** 逐层激活一部分 Transformer block，冻结其余层。它省非激活层的梯度、优化器状态和部分激活；若要更新更早的层，反向仍可能经过冻结层，因此不能把全部激活一并删除。课件主要展示微调实验，层间更新不同步的收敛代价依任务而定。它和 [[Lecture-10_Subspace-Optimizers#6. 分块/逐层训练 LISA|第 10 讲]] 是同一系统思想。

## 3. 自回归推理与 KV Cache

**核心掌握。** 生成 token $t$ 时，模型条件于之前所有 token。每个新 token 的注意力需要历史 token 的 K、V；若每步重算，就浪费大量前向计算。KV Cache 保存历史层、头、token 的 $K,V$。

粗略显存：

$$
\text{KV bytes}\approx
2\times b\times s\times l\times h\times\text{bytes per element},
$$

其中 2 对应 K 和 V；若多头维度与 $h$ 不同，要按实际每层 KV 宽度计算。上下文长、批量大、层多时，KV Cache 会成为长上下文推理的主内存项。

该简式假定标准 MHA、各层 KV 总宽度为 $h$、K/V 采用相同精度，并只计算有效 token。更一般地用 $2bs\sum_{\ell=1}^{l}n_{\mathrm{kv},\ell}d_{\mathrm{head},\ell}$ 乘每元素字节；GQA/MQA 的 KV 头数少于 query 头数，不能继续套全宽 $h$。分页空闲空间、元数据和压缩潜变量另计，MLA 需按其缓存表示单独计算。

推理有两个阶段：

- **Prefill**：并行处理 prompt，矩阵较大，往往 compute-bound；
- **Decode**：每步只生成少量 token，需要加载历史和权重，往往 memory-bandwidth-bound。

## 4. 减少 KV Cache

### 架构共享

- **MQA**：多个 query 头共享一个 K/V 头，显著缩小缓存；
- **GQA**：将 query 头分组，每组共享一组 K/V，折中质量与带宽；
- **MLA**：联合压缩 K/V 的低秩潜在表示，DeepSeek-V2 使用该路线。

共享 K/V 通常需要预训练配方或继续微调来适配，不是简单运行时开关。

### 稀疏与淘汰

- 观察 attention 具有稀疏性，只保留重要 token；
- H2O 用 heavy hitters 动态淘汰，保留对生成影响大的历史；
- StreamingLLM 观察到 attention sink：即使初始 token 语义不突出，也常获得大权重；保留部分 sink token 与最近窗口可稳定流式生成；
- Quest 保留完整 KV Cache，但按 query 与块级相关性只加载关键块参与 attention；主要减少访问/计算，不等于永久删除缓存或保证降低全部常驻容量。这正是它与 eviction 方法的区别。

### 跨层共享与量化

KV Cache 在相邻层可能相似，可设计跨层共享或近似压缩；课件第 25 页的 CLA 需要训练适配，不能仅凭相似性把任意预训练模型的缓存直接替换。量化时可针对 key/value 的不同分布分别处理，例如 KIVI 的 key 用 per-channel、value 用 per-token；这是具体方法的配方，非所有模型/位置编码下的固定最优策略。

## 5. vLLM 与 PagedAttention

**核心掌握系统思想。** 朴素批处理为每个请求预分配最大可能长度的连续 KV 空间，导致：

- 内部碎片：预留过长；
- 外部碎片：不同长度请求很难填满；
- 无法方便共享相同前缀。

PagedAttention 借鉴操作系统虚拟内存和分页：把 KV 存成固定大小 block，逻辑连续、物理可不连续，用 block table 把逻辑块映射到物理块，并按需分配。

收益是提升显存利用率、允许请求细粒度拼接与退出，并支持前缀共享；讲义报告在相近延迟下吞吐提高约 2-4 倍。这个数字来自特定模型、负载和基线对比，不是任意部署的保证。它主要解决 **KV 管理效率**，不等同于减少单次 attention 的数学 FLOPs。

## 6. 投机解码

**熟悉。** 标准自回归 draft model 顺序提出 $K$ 个候选 token，target model 在已给出的候选序列上并行计算各位置的条件概率；按序接受前缀，第一次拒绝后丢弃剩余候选，并从校正分布采样。全部接受时，再从 target 的下一位置分布采样一个 token；需另处理 EOS 和长度上限。验证机制设计正确时输出分布可与 target model 保持一致，不代表同一随机种子下逐 token 必然完全相同。

**熟悉条件，仅作了解推导细节。** 在一个固定前缀下，记实际采样规则处理后的目标分布为 $p$、提议分布为 $q$，先采样 $z\sim q$，以 $\min(1,p(z)/q(z))$ 接受。拒绝时从下式采样：

$$
r(z)=\frac{[p(z)-q(z)]_+}{\sum_y[p(y)-q(y)]_+},
\qquad [a]_+=\max(a,0).
$$

提议已采出的 token 满足 $q(z)>0$；拒绝概率非零时分母才需计算。单个 token 的总概率为 $\min(p(z),q(z))+[p(z)-q(z)]_+=p(z)$，解释了校正的必要性。若 $p=q$ 则全接受，无需定义零分母的校正分布。温度、top-$k$/top-$p$ 等规则必须先纳入各自的实际分布。该补充来自 [Leviathan 等第 2.3 节与 Algorithm 1](https://arxiv.org/abs/2211.17192)，不是课件示意图已经给出的完整证明。

它适合“预测容易、验证可并行”的负载；K 过小收益有限，K 过大浪费 draft 计算。讲义报告在合适设置下约 2-3 倍加速，具体数值依赖模型对、数据和硬件。

## 7. 训练与推理成本对照

| 技术 | 训练收益 | 推理收益 | 关键代价 |
|---|---|---|---|
| LoRA/DoRA | **可训练参数**及其梯度、优化器状态大幅缩小 | 合并后可能降低增量成本 | 子空间表达有限 |
| Adapter | 缩小可训练参数 | 保留额外层 | 结构改动 |
| LISA | 缩小梯度/状态/部分激活 | 不直接改善推理 | 可能增加收敛步数 |
| GQA/MLA | 训练适配 | 减少 KV Cache 与带宽 | 架构与训练成本 |
| H2O/StreamingLLM | 不适用 | 减少历史 KV | 可能丢失远距离信息 |
| PagedAttention | 不适用 | 提升缓存利用率与吞吐 | 内存管理复杂 |
| 投机解码 | 不适用 | 并行验证多个 token | draft 误差/浪费 |
